## Implementation and experiments

- Dashboard transport/mix/assignment request types permit omitted timestamp; server resolves now +5000 ms using its clock, returns/broadcasts it, and preserves original timestamp on idempotent replay. Explicit API schedules keep the 1500 ms minimum lead. Prepare needs no timestamp. Source scan found no other production operator timing gates; operator display profile is now internet. Participant strict opt-in/default low-level estimator remain deliberate options, not operator command gates.
- Server replays one missing current preparation per status, guarding frozen membership and current show/transport/assignment/map identities. Transport/assignment replay waits for known channel hashes; real client checks output warmup. Assets replay only after verified hashes, preventing status-driven downloads. Repeated good status after ACK returns snapshot. Late ACKs after commit reject. Panic also clears uncommitted assignment preparation/selection, preventing unintended recovery after an emergency stop. New joiners outside frozen membership still need a new preparation.
- Download campaigns are deduplicated per phone/cache, queued at maximum two concurrent tracks, max four attempts. Retry waits 2–4 / 4–6 / 8–10 seconds, or bounded Retry-After plus jitter; inactivity timeout 30 seconds covers both response headers and stalled body. Slow progressing transfers are permitted beyond that window. Hash/decode/budget/oversize/404 errors do not retry. Failure cooldown 60 seconds survives repeated preload callers. User retry honors the same cooldown. Obsolete show/unmount work aborts active requests/backoff and prevents queued requests/cache publication.
- Regression at 250 simulated independent caches during persistent outage: exactly 1000 requests (four per phone for one track), despite overlapping/repeated preload calls; retry delay distribution varies across phones. This is a deterministic local unit scenario with injected waits, not a 250-browser/venue test or a wall-clock request-rate benchmark.
- New regression failures were test-fixture issues: first recovery test put deviceId on a strict wire envelope (correctly rejected); corrected the fixture. Backoff cancellation test initially used Bun's eager rejects assertion before firing abort, timing out; changed test to collect the rejection and abort before asserting. Logs retained; implementation limits/assertions unchanged.
- Used React best-practices skill checklist on touched components: no hooks in conditions, explicit retry dependency, existing preload dedup shared across gesture/effect, unmount cancellation, alert/button semantics preserved, no new package or listener loop. Server/client/admin gates and local E2E details follow.
