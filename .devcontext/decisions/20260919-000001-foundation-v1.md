# Establish a runnable repository boundary before feature teams split

Date: 2026-09-19. Status: accepted for the user-requested foundation. Affected teams: all four.

## Context

The user requested a prepared repository and a plan ready to hand to four independently orchestrated teams. A folder-only scaffold would leave package setup, protocols, mocks, and commands to diverge. Completing the actual concert before splitting would consume the teams' feature scope and requires physical equipment that is not available to this preparation task.

## Decision

Use Bun 1.3.14 with the source's pinned compatible Next/React/Hono/Zod versions. Keep active workspaces separate from the reference source. Provide v1 Zod/JSON Schema boundaries, a full OTC codebook, deterministic synthetic fixtures, meaningful foundation tests, typed package seams, a health-only real backend, labeled development frontend previews, and explicit Python validation/replay commands. Unimplemented operations return an error, never fake success.

Only `epochNow()` is extracted in this foundation. Team 1 owns the NTP estimator/lifecycle extraction and source baseline characterization; Team 2 owns real audio extraction; Team 3 owns actual video generation/decoding; Team 4 owns interactive operator controls. Move hardware checks out of the serial software-foundation gate and into the first parallel team milestones. Preserve all final performance targets as pending measurements.

Freeze the shared interface at `foundation-v1` and create four local feature branches from the same commit. Runtime schema generation and fixtures must remain reproducible. Root scripts/CI/contracts/testkit remain captain-owned. Publish the baseline to the existing remote separately when the captain distributes it.

## Alternatives and consequences

- Empty directories would not prove that independent development commands work.
- Implementing the concert in the scaffold would overrun preparation scope and give false confidence without hardware tests.
- The mock API intentionally supports only snapshots, assets, explicit event broadcasts, and clock probes. Teams extend owned adapters or coordinate changes to shared testkit; they must not assume real mutations already exist.
- Existing large source modules are not copied wholesale. Attribution/provenance is recorded for the small extraction already made and for future extraction candidates.
